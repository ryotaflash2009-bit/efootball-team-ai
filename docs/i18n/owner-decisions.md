# 多言語: 本人の判断が必要な点と Claude Code の推奨（2026-10-06）

技術の検証（基盤・下書き・疑似ローカライズ・RTL の準備）は済んだ。公開には次の判断が必要。各項目に推奨を付ける。

| # | 判断 | 選択肢 | 推奨 | 理由 |
|---|---|---|---|---|
| 1 | Production へ公開する言語 | (a) 当面は日本語・English だけ / (b) 下書きの言語を「試験版」として公開 / (c) 1〜2 言語をレビューして公開 | **(a) の後に (c)**。最初の候補は **es・pt-BR** | 下書きは 4,495 中 131（2.9%）だけで、計算ライブラリの文章・能力名・法務文書は英語のまま。試験版でも混在が大きく、品質の印象を損ねる。es・pt-BR は利用者の多い地域の言語で、能力名の公式の表記の確認もしやすい |
| 2 | 翻訳品質の最終承認 | 本人 / ネイティブのレビュー担当 / 専門の翻訳者 | **言語ごとにネイティブのゲーム利用者 1 名のレビュー + 本人の承認** | UI・サッカー用語は、ゲームを知るネイティブの確認が最も効果的。`reviewedBy` に記録し、監査が `VERIFIED_REVIEWED` を確認する |
| 3 | 法務文書の基準言語 | 日本語 / English | **日本語（運営者が作成した原文）** | 現状の原文。English は v1.0 の訳 |
| 4 | 矛盾したときに優先する言語 | 日本語 / English / 未定 | **専門家の確認まで未定のまま**（推奨は日本語） | 準拠法・裁判管轄が未確定（`docs/release/legal-review-checklist.md`）。推測で決めない |
| 5 | サポートの対応言語 | 日本語・English / ほかも | **日本語・English だけ**（ほかの言語は英語での返信になる旨を明記） | 運営者 1 名で、迅速な返信を約束できない |
| 6 | アラビア語を正式に公開するか | 公開 / 延期 | **延期** | 位置の指定（`left-`/`right-` 43・`translate-x` 9）・スライダー・ピッチ・共有カードの RTL が未完成。疑似 RTL で基本の反転は確認済み |
| 7 | 選手名・監督名の翻訳 | データ元の名称だけ / 独自の音訳 | **データ元の名称だけ**（ja 以外は英語名） | 根拠のない音訳は表記の揺れと権利の問題を生む。データ元が各言語の名称を持った場合だけ使う |
| 8 | 固有名称の表記 | 翻訳する / しない | **しない**: TeamAIXI・eFootball™・KONAMI・World・OVR・Link-Up Play・AI Best XI・カード種別・プレースタイル名・スキル名 | ゲーム内の表記と一致させるため。能力名は各言語のゲーム内の公式の表記を確認してから辞書へ（用語集の `draft` を `approved` に） |
| 9 | 専門の翻訳の必要性 | 必要 / 不要 | **法務文書は必要（公開する場合）。UI はネイティブのレビューで足りる** | 法務文書を機械・AI の訳だけで公開しない |
| 10 | v1.1 の多言語のリリース日 | 日付 | **日付は決めず、条件で決める**: 1 言語の全文（4,495 キー + 表示層の文章 + 能力名）の翻訳・レビュー・多言語 black-box の合格の後 | 現状の下書きの量（2.9%）から、最初の言語でも残りの作業が大きい |

## 公開までの残りの作業（言語ごと）

1. 残りのキー（約 4,364）の翻訳（用語集に沿って）
2. 表示層の文章（診断・比較・育成・スカッドの説明）を「キー → 言語ごとの文」へ作り直す（`architecture.md` §6）
3. 能力名・ゲームの用語を、その言語のゲーム内の公式の表記と照合
4. CJK の言語: 共有カードの画像のフォントの確認（`document.fonts.check()`）
5. ネイティブのレビュー → `locale-status.json` の `quality`・`reviewedBy` を記録 → `--record` で hash を記録
6. その言語の多言語 black-box（公開画面 × 5 viewport）に合格
7. registry の state を `PUBLISHED` にする PR（その言語だけを `SUSPENDED` に戻せる）
