# 改善シミュレーション（2026-10-07・v1）

`src/lib/squad/improvement-simulation.ts`（規則の版 `squad-improvement-simulation/2026-10-07.v1`）・画面 `ImprovementSimulationPanel`
（スカッドの編集 → 診断の下の折りたたみ「改善シミュレーション」）。

- 仮の変更を診断の入力に当て、**同じ診断エンジン（`diagnoseSquad`）** で前後を比べる。生成 AI・主観は使わない。決定的・保存しない・自動で適用しない。
- 比べるもの: 総合・各カテゴリ（攻撃・守備・空中戦・スピード・パス・ドリブル・プレス・カウンター・充足）・弱点の増減・称号とバッジ（前後）。
- 対応する変更: 先発と控えの入れ替え（`swap`）・先発の配置ポジションの変更（`move`。GK とフィールドの間は拒否）。
- 対応しない変更（能力値の再計算が必要なため・次の版の候補）: 監督の変更・フォーメーションの変更・育成の変更。
- 入れ替えの候補: 全部の組み合わせ（GK は GK とだけ・カードの無い枠は除く）を試し、総合の改善が大きい順に最大 3 件。
  同点は「悪化したカテゴリの数が少ない → 先発のキー → 控えのキー」の順。総合が判定できないスカッドでは出さない。
- 計算量: 先発 11 × 控え 12 で約 16 ms（折りたたみを開いたときだけ）。
- テスト: `improvement-simulation.test.ts`（8 件: 改善の検出・入力の不変・決定性・キャプテン・適性・GK の拒否・存在しないキー・順位・同点・判定不能）。

## v2: フォーメーションの変更（2026-10-09）

- 改善シミュレーションの欄に「フォーメーションを変えた場合」（総合が上がる上位 3 件）を足した（`rankFormationChanges`・`simulateFormationChange`）。
- 割り当ては **アプリの実際のフォーメーションの変更（`changeFormation`）と同じ**: 元のフォーメーションの既定のポジション →
  同じポジションの枠 → 同じ役割（GK/DF/MF/FW）→ 残りの空き枠。あふれた選手は控え（満員なら外れる）。キャプテンは同じ枠 ID が残れば残る。
  変更の直後は配置の上書きが無いため、選手のいる枠のポジションは既定の座標から推定（`inferFreshRole`）。
  全 90 通りのフォーメーションの組み合わせ × 3 つのスカッドで、枠・控え・外れる選手・キャプテンがアプリと一致することをテストで確認。
- 能力値は配置に依存しない（育成・ブースター・監督の補正は選手ごと）ため作り直さない。選手が外れる変更は候補にしない。
- 監督・育成の変更は引き続き対象外（能力値の再計算が必要）。
- 確認: `improvement-simulation.test.ts`（11）・`black-box-diagnosis-facts.mjs`（16/16・開いてから 319 ms）。
