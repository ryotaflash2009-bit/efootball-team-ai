# F-034 能力値直接操作・スライド式育成UI（Mobile Ability-Direct Slider Progression Editor）

状態: verified（PR #80、公開 black-box 8 viewport 309/309、2026-09-27）。Phase 2 の中核UI・高優先度（本人指定 2026-09-27）。

## 1. 本人の要望

スマホの育成UIが使いにくい。上げたい能力値そのものをタップし、関連する能力を見ながら、その場で育成したい。

- ＋／－ で1段階ずつ、横スライダーで複数段階を一気に動かす。
- ドラッグ中も能力値・必要ポイント・残りポイントがその場で変わる。
- カテゴリ別の配分（パス・ドリブル・クイックネス・脚力・エアバトル等）を画面下部で常に確認できる。
- 保存は既存の明示的な保存操作で行う。

## 2. UX のベンチマーク（eFHUB）と、コピーしないもの

参考にしたのは抽象的な UI/UX 原則だけ。

- 能力値と育成を同じ画面で扱う。
- 能力値そのものを操作の入口にし、選択中と関連する能力を強く見せる。
- 画面下部から、＋／－ とスライダーで育成する。
- 配分と残りポイントを常に見せ、画面の往復を減らす。

次のものはコピーしていない: ソースコード、CSS、ロゴ、商標、カード画像、背景素材、固有アイコン・フォント・文章・アニメーション素材、独自アセット、非公開データ。
名称・配色・部品・トークンはすべて eFootball Team AI 独自のもの（`globals.css` の `--cat-*`、`.ability-row`、`.progression-dock` 等）。

## 3. 仕様（単一の真実源）

| 項目 | 使うもの |
|---|---|
| 能力 → 育成カテゴリ、カテゴリ → 関連能力 | `src/lib/progression/stat-groups.ts` の `PROGRESSION_GROUPS`（`groupIdForStat`）。UI 側に対応表を持たない |
| コスト | `progression-rules.ts` の ruleset（`costForNextLevel = 1 + floor(level / 5)`、累積コスト）。スライダーの値は**カテゴリレベル**で、消費ポイントではない |
| 上限・残りポイント・丸め | `group-allocation.ts` の `adjustGroupLevel` / `maxUsefulLevelForGroup` / `summarizeGroupPoints` |
| 最終値（育成・ブースター・監督・その他） | `engine.ts` の `calculateBuild`（プレビューも同じ関数・同じ条件） |
| 表示名 | 日本語は `stat-labels.ts`（例: クイックネス・脚力・エアバトル）、英語は `stats.ts` / `stat-groups.ts` の正式名 |

UI 状態の制御は `src/lib/progression/ability-direct-editor.ts`（純関数と reducer）。＋／－・キー操作・スライダーの確定・元に戻すは、すべて同じ `adjustGroupLevel` を通る。

## 4. 画面

- **能力一覧（育成の入口）**: 行は button（`aria-pressed`）。選択中 = カテゴリ色の強い発光と「選択中」ラベル、関連 = カテゴリ色の枠と ◆、無関係 = 少し暗く（opacity 0.62・押せる）。左右2列に分かれていても同じカテゴリなら同時に強調。変更前 → 変更後と差分（+3 等）を短い演出つきで表示。
- **画面下部の育成パネル**（本文の最後に sticky。本文を隠さず、最後の能力までスクロールできる。safe-area 対応）:
  - 選択中の能力・育成カテゴリ・残りポイント（少ないと警告色）・選択解除
  - カテゴリ Lv（変更前 → 変更後・差分）、必要ポイント／返却ポイント、次の強化、最大到達
  - − ／ スライダー ／ ＋（44px 以上）
  - 状態: ポイント不足（到達不能区間は斜線）、カテゴリ最大（MAX）
  - 関連能力のプレビュー、内訳（基礎・育成・ブースター・監督・その他・最終）
  - 全カテゴリの配分チップ（横スクロール・選択中を自動表示・タップでカテゴリ選択）
  - 元に戻す（選択時点のレベルへ）、保存へ（既存の保存欄へ移動）
- 未選択時は、ヒント・残りポイント・配分チップだけの細いバー。
- モバイルでは能力一覧を先頭に表示（従来のカテゴリ別スライダー一覧・自動育成・保存欄はその下。PC では左列）。

## 5. スライダー

- 値 = カテゴリレベル（0 〜 能力99までの上限）。整数に snap、到達可能上限で止まる。
- ドラッグ中はプレビューだけを計算し、指を離したときにビルドへ反映する。通信 0。
- `pointercancel`（縦スクロールへの移行など）はドラッグを取り消し、元のレベルに戻す。`touch-action: pan-y` で縦スクロールはブラウザーに任せる。
- キーボード: ← → ↑ ↓ で ±1、Home で 0、End で到達可能上限。`role="slider"`、`aria-valuemin/max/now/valuetext`、`aria-describedby`（状態の説明）。

## 6. 保存

能力のタップ・スライダー操作だけでは保存しない。保存は既存の保存欄（未ログイン = このブラウザーの localStorage、ログイン済み = アカウント別領域）。選択中の能力・ドラッグ中のプレビュー等の UI 状態は保存しない。

同時に直した既存の不具合: 選手詳細の保存欄（`BuildBar`）と比較画面（`PlayerControlColumn`）は、保存先スコープが決まる前に一覧を読んでいたため、再読込直後に保存済みビルドが表示されなかった。スコープの確定・切替で読み直すようにした。
