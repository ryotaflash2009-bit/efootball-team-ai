# Integrated roadmap (統合ロードマップ)

作成: 2026-09-27。機能ごとの状態は `feature-ledger.md`、原案の出典は `original-vision-traceability.md`。

## 1. 基本方針

- 優先順位（本人指示 2026-09-27）:
  1. データ保護・プライバシー・認証・重大エラー
  2. 正確性
  3. 公開中の機能の不具合
  4. 体感速度
  5. My Team・ビルド・診断の中核
  6. 共有・成長
  7. 友達・比較
  8. 称号・ランキング
  9. コミュニティ
  10. 生成AI・画像
  11. 課金
  12. ネイティブアプリ
- 1機能ずつ Release Gate（tests・Build・black-box・desktop/mobile・security・a11y・性能・文書・公開環境確認）まで完了させてから次へ進む。
- コミュニティは、認証・公開範囲・安全機能（ブロック・ミュート・通報）が verified になるまで公開しない。
- 生成AI API・画像認識・課金は、費用・安全・個人情報・契約を先に評価する（本人の契約操作が必要）。
- 原案が曖昧なものは推測で確定しない。
  - feature flag 下の仮実装や fixture までは進める。
  - 本人の判断が必要な点だけを最大5件にまとめて質問する（§4）。

## 4. 本人に確認したい点（回答がなくても §3 は進める）

- **Q1 共有URL（F-042）** — 本人の判断は要りませんが、方式だけ報告します。
  - 採る方式：A「URL に要約を載せる（サーバー保存なし）」。B「サーバーに保存して短い URL」は認証・削除・濫用対策が必要。
  - 推奨：A を MVP とし、B は Phase 4 の公開範囲と合わせて検討。
- **Q2 完全ゲームプラン（F-033）** — 範囲の確認。
  - 原案：「完全ゲームプラン」（本人指示）と Game Plan 風の配置編集（実装済み）。
  - 不明点：個別指示・攻守の戦術設定まで含めるか。
  - 選択肢：A「配置＋キャプテン等（現状）で完成とする」 / B「ゲーム内の個別指示・戦術まで再現」。
  - 推奨：B は公式の仕様データが必要なので、データ源が確認できるまで A で完成扱い。
- **Q3 称号・バッジ（F-072）** — 付与の基準。
  - 選択肢：A「診断カテゴリの上位（例：空中戦 S）を称号にする」 / B「所持カードの特徴（例：特定リーグ中心）」。
  - 推奨：A（既存の診断だけで決定的に計算でき、推測を含まない）。
- **Q4 Tier・Pack（F-090 / F-092）** — データ源。
  - どのサイトの Tier・Pack 情報を使うか（利用規約の確認が必要）。
  - 推奨：確認が取れるまで「準備中」のままにする。
- **Q5 課金・Pro（F-120）** — 開始時期。
  - 推奨：招待ベータの間は無料のみとし、Pro の境界（F-044）は設計だけを維持。

## 5. 本人判断（2026-09-27、§4 への回答）

- **Q1 共有URL:** URL に要約を載せる方式（サーバー保存なし）。スカッド名・ID・メール等は一切含めない。F-042 で verified。
- **Q2 完全ゲームプラン:** 現在の配置編集を MVP 完成版とする。個別指示は、公式または許諾済みの信頼できる仕様を確認できるまで deferred（推測で実装しない）。
- **Q3 称号・バッジ:** 既存の診断カテゴリ、確定済みの計算規則、パーセンタイルを基準にしたルールベース。人気や生成AIの主観では付与しない。閾値・計算式・データ母数・更新時点を文書化し、最初は少数の意味のある称号に限定する。
- **Q4 Tier・Pack:** データ源の利用許諾・Terms・取得方法が確認できるまで「準備中」を維持する。外部サイトの評価を無断で取得・転載しない。自前の確定データだけで作れるルールベースの分析は設計してよい。
- **Q5 課金・Pro:** 招待制ベータ中は無料のみ。決済・課金・Pro 契約は実装せず、導線も公開しない。有料候補の機能分類と費用試算は可。ベータの利用結果を見て再判断する。
