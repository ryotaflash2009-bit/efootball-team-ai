# 完全なゲームプラン（2026-10-07・ローカルだけ）

スカッドの編集の下の「ゲームプラン」の欄。先発・控え・フォーメーション・配置・キャプテン・セットプレー・監督・Link-Up は
既存のスカッドのまま使い、次を足す。

| 項目 | 内容 | 制限 |
|---|---|---|
| チームの指示 | 攻撃の型（監督の戦術の 5 つと同じ名前）・守備のライン・プレスの強さ・メモ | メモ 200 文字 |
| 交代の計画 | 時間（1〜120 分・任意）・下げる先発の枠・入れる控え・理由 | 最大 6 件 |
| 代わりの計画 | 切り替えるフォーメーション（今と違うもの）・切り替える場面・メモ | — |
| 相手ごとの計画 | 相手の名前（メモ）・傾向（ボール保持・前からのプレス・速いカウンター）・調整（相手の分析の 6 つ）・メモ | 最大 5 件 |
| 確認が必要な点 | 枠が無い・枠に選手がいない・控えにいない・同じ選手や枠の重複・時間の順・代わりの計画の矛盾 | 保存は止めない |
| 書き出し・読み込み | JSON（`game-plan-export/2026-10-07.v1`）。スカッドの ID・名前・選手の名前は含めない。読み込みは 32 KB まで | 違うフォーメーションからの読み込みは案内を出す |

## 保存とデータの扱い

- 端末の localStorage の別のキー `efootball-team-ai:local:{guest|account:<scopeId>}:game-plans:v1`（スカッドの ID ごと）。
  **スカッドの保存の形（StoredSquad）は変えない**（保存の互換性を保つ）。サーバーへ送らない。
- スカッドの複製でゲームプランも写し、スカッドの削除で消す（`squad-storage.ts`）。
- 「ローカルデータをすべて削除」は従来どおり旧共通領域だけが対象（アカウント別の領域のデータは対象外という既存の方針と同じ）。
- ローカルのバックアップ（`local-backup`）には今回は含めない（バックアップの形式の変更は別の判断）。書き出し（JSON）で代わりに保存できる。
- 文字は表示だけに使い、制御文字・双方向の制御文字を取り除く。Production の migration はしない。
