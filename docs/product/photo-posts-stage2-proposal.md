**`photo_posts` 表:**

**`photo_post_audit` 表:**

## 2. Storage バケット（提案）

| 項目 | 値 |
|---|---|
| 名前 | `photo-posts` |
| 公開 | **非公開**（`public = false`。公開 URL を作らない。表示は署名つき URL・短い有効期限） |
| 上限 | 5 MB |
| MIME | `image/jpeg`・`image/webp`（端末で再エンコード済み。EXIF・GPS は除去済み） |
| キー | `<auth.uid()>/<32 桁の 16 進>.<jpg\|webp>`（推測困難・先頭フォルダーが所有者） |
| 上書き | しない（UPDATE のポリシーなし。変えるときは削除して投稿し直す） |

## 3. Storage Policy（提案）

`storage.objects` に、authenticated だけの 3 件:
- select・insert・delete。
- 条件は `bucket_id = 'photo-posts'` かつ `(storage.foldername(name))[1] = auth.uid()::text`。
- insert はキーの形も検査する。

anon・public にはポリシーを作らない。

## 4. RLS（提案）

`photo_posts`:
- enable + force。
- authenticated だけの select・insert・update・delete。
- すべて `user_id = auth.uid()`。update は USING と WITH CHECK の両方。

無条件の許可（`true`）は使わない。

## 6. 削除後の契約

1. 本人が投稿を削除すると行を消す（hard delete）。同じ操作で画像のオブジェクトも消す。
   - アプリは画像を先に消し、失敗したら投稿を消さずに再試行を案内する。
2. 削除後は、本人を含む誰もその投稿・画像を読めない。
   - 署名つき URL は短い有効期限（5 分以内）にし、削除後に新しい URL を出さない。
3. 監査ログには「削除した」事実だけが残る（本文・画像なし）。
4. 退会（`auth.users` の削除）では、投稿は cascade で消える。
   - Storage のオブジェクトは退会処理の中で本人のフォルダーを消す。サーバー側の処理で、承認後に実装する。
5. Backup:
   - 投稿は参照データの Backup の対象外。
   - 利用者データの Backup を作る場合は保持期間を規約に書く（本人の判断）。

## 7. URL 限定の公開範囲の契約（段階 3・未実装）

- `visibility = 'link'` の投稿は、推測困難な共有トークンを知っている人だけが読める。
  - トークンは 128 ビット以上で、投稿ごとに別。再発行で古いトークンを無効にする。
- 読むのはサーバーの関数（トークンを引数に取る）経由だけ。表の select ポリシーは本人のままにする（一覧に出さない）。
- 検索エンジンに出さない（`noindex`）。トークンをログ・分析に残さない。
- ブロックした相手には、トークンを知っていても表示しない。
- 通報で一時非表示になったものは、トークンでも表示しない。

## 8. 友達限定の公開範囲の契約（段階 4・未実装）

- 友達は双方向の承認で成立する（片方の申請だけでは見えない）。
- 次の場合は、すぐ見えなくなる:
  - どちらかが解除またはブロックしたとき
  - 公開範囲を変えたとき
- `friendships(user_a, user_b, status, created_at)`:
  - RLS で本人が関係するものだけ読める。
  - 投稿の select ポリシーに「本人、または承認済みの友達で、ブロックしていない」を加える。
