# F-071 カテゴリ別パーセンタイル — 設計（実装前）

状態: design（2026-09-27）。Production・DB スキーマ・外部 API の変更は含まない。F-072 称号・バッジ（本人判断 Q3：ルールベース、パーセンタイル基準可）の前提。

## 1. 何を示すか

「このスカッドの空中戦 72 点は、全カードの中でどのくらいか」を、推測を含まない数値で示す。

| 対象 | 意味 | 算出元 |
|---|---|---|
| カード単位（既存） | 能力値ごとの順位。「順位集計時点の全 N 件中」 | 公式参照データの `ranks_json`（`valuePercentile`、`src/lib/world/player-analysis.ts`） |
| カテゴリ単位（新規） | 1枚のカードのカテゴリ値（診断と同じ能力集合の平均）が、全フィールドプレイヤーカードの中で何%の位置か | World 参照データから算出した分布表 |
| スカッド単位（新規） | 先発フィールドプレイヤーのカテゴリ値の平均（＝診断スコアの元の値）が、カード単位の分布のどこにあるか | 同じ分布表 |

スカッド単位は「他のユーザーのスカッドとの比較」**ではない**（利用者データを集計しないため）。表示文言は「全カード（GK除く）の中での位置」とし、「上位 ◯% のスカッド」とは書かない。ユーザー間の比較は F-074（利用統計が必要・本人判断待ち）で扱う。

## 2. 分布表の作り方

- 母集団: World 参照データのうち GK を除くカード。診断と同じ条件で、能力値が全キー揃うものだけ。
- 値: 診断と同じ「標準最終値」（`StatBreakdown.finalValue`、`squad-diagnosis.ts` の `perPlayerCategoryValue`）。カテゴリ定義は `ABILITY_CATEGORIES` をそのまま使う（別定義を作らない）。
- 形式: カテゴリごとに 0〜100 パーセンタイルの境界値 101 個（`p0 … p100`）と、母数 `n`、参照データの `sourceChecksum`、生成日時、ルール版（`rulesVersion`）。数 KB の静的 JSON。
- 生成: リポジトリ内のスクリプトで、公開済み参照データ（読み取りだけ）から生成し、JSON を PR でコミットする。実行時に DB へ集計クエリを投げない。
- 更新: 参照データの Apply 後（applied-state の checksum が変わったとき）に再生成する。分布表の `sourceChecksum` と現在の applied-state が違えば「集計時点」の日付を表示する（値は隠さない）。

## 3. 表示と規則

- 表示: 「空中戦 72 点（全カード中 上から約 18% の位置・集計 2026-09-26 時点・母数 11,xxx 枚）」。
- 丸め: 整数%。母数 < 500 のカテゴリは表示しない（分布が粗いため）。
- 境界: 同値は「その値以下の割合」で数える（既存 `valuePercentile` と同じ向き）。
- 共有 URL・履歴には入れない（URL 契約 `sd1` を変えないため）。表示時に毎回計算する。

## 4. テスト（実装時の Release Gate 追加項目）

- 分布表の検証: 単調増加、101 点、`n` と checksum の形式、カテゴリ集合が `ABILITY_CATEGORIES` と一致。
- 既知の小さな母集団で、パーセンタイルの端（最小・最大・同値）が正しい。
- 分布表が古い・欠けている・壊れているときは、パーセンタイルを出さずに診断本体は通常どおり表示する。
- 文言に「スカッドの上位」「ランキング」を含まない。

## 5. 未確認点（実装前に確認すること）

- 参照データから「標準最終値」を全カード分算出する経路（診断はクライアントで `StatBreakdown` を作っている）。同じ関数をスクリプトから呼べるかを確認する。呼べない場合は実装せず、この文書を更新する。
- 生成スクリプトが読むのは公開済みの参照データだけにする。Production への接続が必要になる場合は、別承認の対象として止める。
