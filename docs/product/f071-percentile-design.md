# F-071 カテゴリ別パーセンタイル — 設計（実装前）

状態: design（2026-09-27）。Production・DB スキーマ・外部 API の変更は含まない。F-072 称号・バッジ（本人判断 Q3：ルールベース、パーセンタイル基準可）の前提。

## 1. 何を示すか

「このスカッドの空中戦 72 点は、全カードの中でどのくらいか」を、推測を含まない数値で示す。

| 対象 | 意味 | 算出元 |
|---|---|---|
| カード単位（既存） | 能力値ごとの順位。「順位集計時点の全 N 件中」 | 公式参照データの `ranks_json`（`valuePercentile`、`src/lib/world/player-analysis.ts`） |
| カテゴリ単位（新規） | 1枚のカードのカテゴリ値（診断と同じ能力集合の平均）が、全フィールドプレイヤーカードの中で何%の位置か | World 参照データから算出した分布表 |
| スカッド単位（新規） | 先発フィールドプレイヤーのカテゴリ値の平均（＝診断スコアの元の値）が、カード単位の分布のどこにあるか | 同じ分布表 |

スカッド単位は「他のユーザーのスカッドとの比較」**ではない**（利用者データを集計しないため）。表示文言は「全カード（GK除く）の中での位置」とし、「上位 ◯% のスカッド」とは書かない。ユーザー間の比較は F-074（利用統計が必要・本人判断待ち）で扱う。

## 2. 分布表の作り方

- 母集団: World 参照データのうち GK を除くカード。診断と同じ条件で、能力値が全キー揃うものだけ。
- 値: 診断と同じ「標準最終値」（`StatBreakdown.finalValue`、`squad-diagnosis.ts` の `perPlayerCategoryValue`）。カテゴリ定義は `ABILITY_CATEGORIES` をそのまま使う（別定義を作らない）。
- 形式: カテゴリごとに 0〜100 パーセンタイルの境界値 101 個（`p0 … p100`）と、母数 `n`、参照データの `sourceChecksum`、生成日時、ルール版（`rulesVersion`）。数 KB の静的 JSON。
- 生成: リポジトリ内のスクリプトで、公開済み参照データ（読み取りだけ）から生成し、JSON を PR でコミットする。実行時に DB へ集計クエリを投げない。
- 更新: 参照データの Apply 後（applied-state の checksum が変わったとき）に再生成する。分布表の `sourceChecksum` と現在の applied-state が違えば「集計時点」の日付を表示する（値は隠さない）。

## 3. 表示と規則

- 表示: 「空中戦 72 点（全カード中 上から約 18% の位置・集計 2026-09-26 時点・母数 11,xxx 枚）」。
- 丸め: 整数%。母数 < 500 のカテゴリは表示しない（分布が粗いため）。
- 境界: 同値は「その値以下の割合」で数える（既存 `valuePercentile` と同じ向き）。
- 共有 URL・履歴には入れない（URL 契約 `sd1` を変えないため）。表示時に毎回計算する。

## 4. テスト（実装時の Release Gate 追加項目）

- 分布表の検証: 単調増加、101 点、`n` と checksum の形式、カテゴリ集合が `ABILITY_CATEGORIES` と一致。
- 既知の小さな母集団で、パーセンタイルの端（最小・最大・同値）が正しい。
- 分布表が古い・欠けている・壊れているときは、パーセンタイルを出さずに診断本体は通常どおり表示する。
- 文言に「スカッドの上位」「ランキング」を含まない。

## 5. 未確認点（実装前に確認すること）

- 参照データから「標準最終値」を全カード分算出する経路（診断はクライアントで `StatBreakdown` を作っている）。同じ関数をスクリプトから呼べるかを確認する。呼べない場合は実装せず、この文書を更新する。
- 生成スクリプトが読むのは公開済みの参照データだけにする。Production への接続が必要になる場合は、別承認の対象として止める。

## 6. 実装準備の確認結果（2026-09-27）

確認したこと（読み取りのみ・Production 変更なし）:

- 全カードの**基礎能力値**は計算に使える（ローカルの SQLite: 13,009 枚 × 26 能力 = 338,234 行。診断と同じカテゴリ値を全カードで計算できる）。
- ただしローカルの SQLite は古い時点（13,009 枚）。Production は 13,297 枚（2026-09-26 の World 更新後）。ローカルから作った分布は古い。
- **「標準最終値」の分布は一意に決まらない。** 標準最終値は育成配分（ビルド）に依存し、カードごとの正式な配分は存在しない。自動育成（配分方針）は目安のヒューリスティックで、これを全カードに当てた分布は「推測の規則」になる。

そのため、実装の前に本人の判断が必要な点が2つある（推測で実装しない）。

### 判断1: 分布の基準

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| A（推奨） | 育成前（基礎値＋確認済みの付属ブースター・標準モード）の分布。スカッドも**育成前のカテゴリ値**で位置を出す | 規則が確定しており、同じ条件どうしで比べられる | 表示中の診断スコア（育成後）と別の値になるため、「育成前の素質」と明記が必要 |
| B | 基礎値のみの分布と、育成後のスカッドスコアを比べる | 実装が簡単 | 条件が違う値の比較になり、位置が高く出る（誤解を招く） |
| C | 各カードに自動育成を当てた分布 | 表示中のスコアに近い | 自動育成は正式な規則ではない（推測） |

### 判断2: データの出所

| 案 | 内容 | 注意 |
|---|---|---|
| a（推奨） | 承認済みの週1回の更新検出（公開データの全件取得）の結果から、同時に分布表を作る | ワークフローの変更（非秘密の成果物の追加）が必要 |
| b | 公開 API から全件を読み取って作る | 数百リクエストの一括取得になるため、事前の承認が必要 |
| c | ローカルの SQLite（13,009 枚）から作る | 古い時点。更新の約300枚が反映されない |

判断が出るまで F-071 の実装は止める。既存の選手詳細の「物理データの順位・パーセンタイル」（公式参照データの順位そのもの）は影響なし。

## 7. 本人の判断と実装（2026-09-27）

判断: **判断1 = A（育成前の基礎能力値の分布）**、**判断2 = a（週1回の定期検出から作る）**。新しい DB テーブルは作らない。

上の §1〜§4 のカテゴリ単位・スカッド単位は、確定したカテゴリの計算式が無いため**保留**（比較画面の7カテゴリは単純平均で、公式の重みは未確認）。今回は**能力値ごと**のパーセンタイルだけを実装した。

### 規則

| 項目 | 内容 |
|---|---|
| 値 | 各カードの基礎能力値（育成前・World の値）。欠けた値は数えない（育成計算の既定値 40 で埋めない） |
| 同値 | 中央順位（midrank）: 上位割合 = (より大きい件数 + 同値の件数/2) / 母数 × 100 |
| 区分 | 四捨五入した整数%で 上位1%未満 / 上位1% / 上位5% / 上位10% / 上位25% / 上位50% / 中央値未満。「上位0%」は出さない |
| 小さな母集団 | 母数 < 20 は表示しない。< 100 は「上位1%」を出さず「上位5%」から。< 1,000 は「上位1%未満」を出さない |
| 範囲 | 全Worldカード（必須）・同じ登録ポジション・フィールドプレイヤー / GK。1回の表示で範囲を混ぜない |
| 対象外 | 表示中のビルド・育成プレビュー（スライダー）の値のパーセンタイルは出さない |

### 成果物の流れ

1. **A（候補）**: `reference-data-update-detection.yml`（`contents: read` のまま）が、完全な World の行から `world-base-distribution.candidate.json`（能力値ごとの値の件数だけ。名前・ID・URL なし）を作り、Actions の artifact `world-base-distribution-candidate` として 30 日保存する。
2. **B（main へ）**: Production Apply の後の Evidence / applied-state の PR で、その Apply と同じ checksum の候補を `src/lib/percentiles/data/world-base-distribution.json` へ置く。upstream に変化が無い（候補の checksum が applied-state と同じ）ときは、その候補を単独の PR で置いてよい。
3. **C（画面）**: サーバーが main の成果物を main の applied-state と照合し、`DISTRIBUTION_ARTIFACT_VALID` のときだけ `/api/percentiles/world-base` が中身を返す。それ以外（`STALE` / `INVALID` / `INCOMPLETE` / 未生成）は「パーセンタイルデータを現在の選手データと照合できません」だけを表示する。
   - CI（`world-base.test.ts`）は、コミットされた成果物が null（未生成）か VALID / STALE であることを確かめる（INVALID / INCOMPLETE はコミットできない）。

### 表示

- 選手詳細の「能力値」タブ: 能力値ごとの区分、範囲の切り替え、母数と集計日、説明文（「この順位は育成前の基礎能力値を、現在のWorldカード分布と比較したものです」）。
- F-034（育成タブ）: 育成の編集とは別の折りたたみの中に、同じ基礎値の区分を表示する（育成後の値とは混ぜない）。
- 比較画面: トグル（既定はオフ）で、全選手を同じ範囲（全Worldカード）で表示する。
