## 2. スクリーンショットから確認できた UI

- **一覧レイアウト**: カードのグリッド。PC で 7 列前後（幅広）、狭くなるほど列減。カード縦横比は約 3:4（縦長）。
- **選手カードの情報配置**: 左上に大きな OVR（2桁）+ その直下に小さくポジション略号。中央に選手画像。下部に名前（1行・省略）。最下部に星（レア度）。
- **OVR 表示**: 左上・白～明色・非常に大きい。数値のみ。
- **カード間の余白**: 小さめ（4〜8px 相当）。情報密度は高い。
- **一覧上部**: 左に検索欄、右へ横スクロールするフィルタのドロップダウン群（プレイヤータイプ / 状態 / ポジション / プレースタイル / 守備プレースタイル / 能力 / スキル / 基本 / プレーヤーモデル）。総件数（`47,479 人の選手`）を左上に表示。
- **検索中**: 件数が更新され、アクティブ条件がチップ（`"messi" ×`）で表示され、× で解除。
- **サイドメニュー**: 上部固定ヘッダーにロゴ + ナビ。左サイドは eFHUB では水平ナビだが、本アプリは既存の縦サイドメニュー（PC 常時 / モバイル スライドイン）を維持。
- **選手詳細**: 上部にカード画像・名前・ポジション別総合値のグリッド。能力値は 3 セクション（攻撃 / ディフェンス / 身体能力）。各能力は「名称 + 色付き数値バッジ」。色は 赤(〜49)→橙(〜59)→黄(〜69/79)→緑(80〜89)→水色(90+)。ブースト時は `+5` の表記と別色。
- **能力値の色分け**: 数値帯で段階的に変化。色だけでなく必ず数値も併記。
- **スキル表示**: セクション見出し（スキル / プレーヤーモデル）にバッジ/短い行で列挙。
- **プレースタイル**: 名前の下にアイコン + テキスト（例: チャンスメイカー）。
- **ダークテーマ**: ほぼ黒背景。**ライムグリーン**はロゴ・アクティブナビ・アクセント・強調数値に限定使用。
- **情報密度 / ボタン**: 高密度。タップ領域は詰まっているが機能する程度。

## 6. eFHUB ⇔ World の扱い（重要）

- World ID と eFHUB ID は別体系（一部の ID は数値が一致するが同一と仮定しない）。詳細ルートは `/players/world/{worldCardId}` に分離。
- 高信頼リンク（`source_record_links`・1,138 件）のみ確定リンク。`hasEfhubLink=true` の時だけ eFHUB 画像プロキシと eFHUB 補助情報を使う。
- `merge_candidates`（24,826 行）は自動統合しない。`data_conflicts`（59 行）は自動上書きしない。表示は World 値を主。

## 7. 画像方針（外部アクセス 0 を維持）

- 優先1: `hasEfhubLink` かつ eFHUB カード ID が数字のみ → 既存 `/api/player-image/{efhubId}`（efimg.com・**既承認**の経路）。
- 優先2: World 画像（ホスト `d1zxa6glxh8sq9.cloudfront.net`）。**今回は接続しない。** URL は SQLite 保存値を API レスポンスに `imageUrlCandidate` として返すのみ（`<img>` には渡さない）。
- 優先3: ローカル SVG プレースホルダー（`PlayerSilhouette`）。
- World 画像プロキシの設計は `src/lib/world/image.ts` の純関数（ホスト厳密一致検証）として用意。実接続には新ホスト `d1zxa6glxh8sq9.cloudfront.net` への許可が必要 → 本レポートで報告（URL テンプレート: `https://d1zxa6glxh8sq9.cloudfront.net/player_<id>_<ts>.webp`、想定回数: 一覧1ページ 24 枚 × 表示ページ数）。

## 8. ルーティング衝突の回避

- `src/app/players/[id]/page.tsx`（既存・eFHUB サンプル）は据え置き。
- `src/app/players/world/[worldCardId]/page.tsx` を新設。`/players/world/123` は静的セグメント `world` 側が優先されるため `[id]` と衝突しない。

## 9. パフォーマンス方針

- 接続はモジュールスコープに 1 つ（`readOnly: true`）。リクエストごとに開かない。
- 一覧は `LIMIT ? OFFSET ?`。総数は別 `COUNT(*)`。
- 一覧レスポンスに 26 能力値・スキルを含めない（詳細 API でのみ取得）。
- 並べ替え・フィルタ列にインデックス追加（`schema.sql` に `CREATE INDEX IF NOT EXISTS` 追記 + 一度だけ適用スクリプト）。
- 画像は `loading="lazy"`。検索入力は 300ms デバウンス。
- API エラーで画面全体を落とさず `ErrorState` を表示。
