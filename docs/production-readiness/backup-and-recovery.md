# バックアップと復旧設計

調査日: 2026-09-11。本書は設計のみ。実際のバックアップ契約・設定は今回行わない。料金は`cost-estimate.md`と重複する部分があるため、詳細な月額試算はそちらを参照。

## 1. 対象別バックアップ方針(個人開発として現実的な初期値)

| 対象 | バックアップ方式 | 初期値の提案 |
|---|---|---|
| ユーザーDB(Supabase Postgres想定) | Supabase標準の自動バックアップ | 無料プランには自動バックアップが**含まれない**(`authentication-options.md`/`database-options.md`参照)。**Proプラン($25/月〜)への移行が事実上のバックアップ導入条件**になる。 |
| ポイントインタイム復旧(PITR) | Supabase上位プランの機能 | 初期(身内テスト〜招待制ベータ)は日次バックアップで十分と判断し、PITRは一般ベータ以降で検討。 |
| バックアップ保持期間 | Supabase Proプランの標準保持期間に準拠 | 個別確認が必要(契約時に公式ドキュメントで確認)。 |
| 暗号化 | Supabase/Neon等のマネージドDBは、保存時暗号化(at-rest)が標準で有効になっているのが一般的 | 契約時に暗号化仕様を確認する(推測で断定しない)。 |
| 復元テスト | 四半期に1回程度、ステージング環境へバックアップから復元する訓練を実施 | 個人開発では負荷が高いため、まずは「復元手順書を書く」ことを初期のゴールにする(実施は招待制ベータ移行前に最低1回)。 |
| ユーザー単位のエクスポート | 既存のJSONエクスポート機能(保存ビルド)を拡張し、Favorites・My Team・保存スカッド・スカッドテンプレートも含めた「全データエクスポート」機能を将来追加する(`user_exports`テーブル、`data-model-and-isolation.md`) | 実装ロードマップの「11. データエクスポート」で対応。 |
| アカウント削除 | `account_deletion_requests`による猶予期間付き削除(`data-model-and-isolation.md`) | 削除予約から一定日数後に物理削除するバッチ処理を想定。 |
| 誤削除対応 | 猶予期間中の削除取消 + DBの日次バックアップからの個別レコード復元(サポート対応として) | 自動復元UIは作らず、初期版は「上杉さんが手動でバックアップから復元する」運用とする。 |
| DBマイグレーション前バックアップ | マイグレーション実行前に必ず手動スナップショットを取得する運用ルール | CI/CDでは自動化しない(`ci-cd-and-auto-update.md`の「人の承認を残すもの」に合致)。 |
| 参照データの版管理 | `reference-data-update.md`のファイル世代管理方式 | 直近数世代を保持。 |
| 選手データのロールバック | 同上(前版ファイルへの即時切り戻し) | - |
| 障害時の復旧手順 | ホスティング(Vercel)障害時はステータスページ確認+待機、DB障害時はSupabaseダッシュボードでの状態確認+バックアップからの復元、が基本線 | 詳細な手順書は契約後に個別作成する。 |

## 2. RPO(目標復旧時点)・RTO(目標復旧時間)の提案(個人開発として現実的な初期値)

| 段階 | RPO(どこまでデータ消失を許容するか) | RTO(どれだけ早く復旧するか) |
|---|---|---|
| A. 身内テスト | 24時間(日次バックアップ前提) | 数日以内(個人開発者の稼働時間に依存する現実的な値) |
| B. 招待制ベータ | 24時間(同上。PITR導入まではこれが限界) | 1日以内を目標 |
| C. 一般ベータ | PITR導入を検討し、数分〜1時間程度まで短縮を目指す(上位プラン費用とのトレードオフ) | 数時間以内を目標 |

これらは**個人開発として現実的な目標値の提案**であり、法的な保証水準ではない。正式なSLAを謳う場合は別途専門家確認が必要。

## 3. 料金が発生する機能の無料枠/有料時の違い

| 機能 | 無料枠 | 有料時 |
|---|---|---|
| Supabase自動バックアップ | **なし**(Freeプランはバックアップ機能自体が含まれない) | Proプラン($25/月〜)から日次バックアップが有効になる |
| Supabase PITR | Proプランでも別途アドオンの場合が多い(契約時に個別確認) | 追加費用が発生する可能性が高い |
| 参照データのバックアップ | 自前のファイル世代管理のため追加費用なし | ストレージ容量次第(個人開発規模では実質無視できる) |
