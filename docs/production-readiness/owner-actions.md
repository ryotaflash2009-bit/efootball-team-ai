# 上杉さん自身が必要になる操作の一覧

調査日: 2026-09-11。**本書は将来必要になる操作の一覧であり、今回はいずれも実行しない。** 実際に登録・契約・支払いへ進むかどうかは、この設計書一式を確認したうえで上杉さんが判断すること。

各項目について、端末・開くページ・入力情報・費用・支払いの有無・本人確認・二要素認証・秘密情報の扱い・Claude Codeへ渡してよい情報/渡してはいけない情報を整理する。

## 1. GitHubアカウント(Gitリポジトリの置き場所として)

| 項目 | 内容 |
|---|---|
| 端末 | Windows PC(ブラウザーがあればどちらでも可) |
| 開くページ | `github.com`のサインアップページ |
| 押すボタン | 「Sign up」 |
| 入力する情報 | メールアドレス、パスワード、ユーザー名 |
| 費用 | 無料(個人・プライベートリポジトリも無料枠内で利用可) |
| 支払いの有無 | なし(無料プランの範囲では) |
| 本人確認 | メールアドレス確認のみ(通常) |
| 二要素認証 | **強く推奨**(GitHubは2FA設定を推奨・一部機能で必須化が進んでいる) |
| 秘密情報の扱い | パスワード・2FAの回復コードは上杉さん自身が安全な場所に保管する。**Claude Codeには一切渡さない**。 |
| Claude Codeへ渡してよい情報 | リポジトリのURL(パブリックリポジトリの場合)、ユーザー名 |
| Claude Codeへ絶対に渡してはいけない情報 | パスワード、2FA回復コード、個人アクセストークン(PAT)そのもの |

## 2. 認証サービス登録(Supabase想定)

| 項目 | 内容 |
|---|---|
| 端末 | Windows PC |
| 開くページ | `supabase.com`のサインアップページ |
| 押すボタン | 「Start your project」等 |
| 入力する情報 | メールアドレス、パスワード(またはGitHubアカウント連携) |
| 費用 | Freeプランは無料 |
| 支払いの有無 | Freeプランのうちは不要。Proプランへ移行する時点でクレジットカード登録が必要になる |
| 本人確認 | メールアドレス確認 |
| 二要素認証 | 設定推奨 |
| 秘密情報の扱い | プロジェクトのAPIキー(anon key/service role key)が発行される。**service role keyは絶対に公開・共有しない** |
| Claude Codeへ渡してよい情報 | プロジェクトURL、**anon key(公開用の制限された鍵。クライアントに埋め込む前提のキー)** |
| Claude Codeへ絶対に渡してはいけない情報 | **service role key**、DBの管理者パスワード、請求情報 |

## 3. DBサービス登録

Supabase採用の場合、上記2と同一(認証とDBが同一プロジェクト)。代替構成(Neon等)を選ぶ場合は同様の手順が別途必要。

## 4. ホスティング登録(Vercel想定)

| 項目 | 内容 |
|---|---|
| 端末 | Windows PC |
| 開くページ | `vercel.com`のサインアップページ |
| 押すボタン | 「Sign Up」(GitHub連携を推奨) |
| 入力する情報 | GitHubアカウントでのログイン、または独自メールアドレス |
| 費用 | Hobbyプランは無料。Proプランは$20/開発者・月〜 |
| 支払いの有無 | Proプラン移行時にクレジットカード登録が必要 |
| 本人確認 | メールアドレス確認(GitHub連携の場合はGitHub側の確認を流用) |
| 二要素認証 | 設定推奨(GitHub側の2FAが有効ならある程度カバーされる) |
| 秘密情報の扱い | デプロイ用の環境変数はVercelダッシュボード上で設定する(値そのものはClaude Codeへ渡さない) |
| Claude Codeへ渡してよい情報 | プロジェクト名、デプロイURL |
| Claude Codeへ絶対に渡してはいけない情報 | Vercelアカウントのパスワード、支払い情報、環境変数の実際の値(特にDB接続文字列・service role key) |

## 5. 二要素認証の設定(共通)

| 項目 | 内容 |
|---|---|
| 端末 | Windows PC(設定)+ iPhone(認証アプリ、任意) |
| 対象サービス | GitHub、Supabase、Vercel(いずれも設定推奨) |
| 入力する情報 | 認証アプリ(Google Authenticator等)が生成するコード、またはSMS |
| 秘密情報の扱い | **回復コード(recovery code)は絶対にClaude Codeへ渡さない**。印刷して物理的に保管するか、パスワードマネージャーへ保存することを推奨。 |

## 6. 請求情報の登録

| 項目 | 内容 |
|---|---|
| 端末 | Windows PC |
| 対象サービス | 各サービスの「Billing」設定画面(無料枠を超える契約をする時点で初めて必要) |
| 入力する情報 | クレジットカード情報(または対応する決済手段) |
| 費用 | サービスごとの月額(`cost-estimate.md`参照) |
| 支払いの有無 | **あり**(このステップが実際の支払い発生ポイント) |
| 本人確認 | カード情報の入力自体が本人確認を兼ねる場合が多い |
| 二要素認証 | 決済確定時に追加の本人確認(3Dセキュア等)を求められる場合がある |
| 秘密情報の扱い | **カード番号・セキュリティコードは、いかなる場合もClaude Codeへ入力・共有しない**(このルールは絶対厳守) |

## 7. 無料枠設定・利用上限設定

| 項目 | 内容 |
|---|---|
| 端末 | Windows PC |
| 対象サービス | Vercel/Supabase等の「Usage」「Billing Alerts」設定画面 |

## 11. バックアップ確認・ステージング確認・本番公開承認

これらは登録・契約を伴わない日常運用の操作。Claude Codeが提示するチェック結果を見て、上杉さんが目視確認・承認ボタン操作を行う(`ci-cd-and-auto-update.md`参照)。

## 12. Claude Codeへ渡してよい情報 / 絶対に渡してはいけない情報(総括)

### 渡してよい情報

- 公開URL・プロジェクト名・ドメイン名
- 環境変数の**名前**(値ではない)
- 公開鍵・anon key(クライアントに埋め込む前提で設計された、制限付きの鍵)
- エラーメッセージの内容(個人情報を含まない範囲)

### 絶対に渡してはいけない情報

- 各種サービスのログインパスワード
- 二要素認証の回復コード・シークレットキー
- **Service Role Key(SupabaseのRLSをバイパスする鍵)**
- クレジットカード番号・セキュリティコード・請求先住所
- DBの管理者接続文字列(パスワードを含むもの)
- 本人確認書類の画像等
