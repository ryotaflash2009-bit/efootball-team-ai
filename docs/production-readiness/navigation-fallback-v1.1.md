# 止まった画面の移動の早めの戻し（v1.1・2026-10-07）

## 問題（2026-10-05・2026-10-06 の確認）

新しいブラウザーの最初の client の移動で、まれに Next.js の router の transition が確定しない（RSC の応答は約 0.3 秒で届き、
React が commit しない）。安全策（`src/lib/navigation/navigation-watchdog.ts`）は 5 秒後に同じ URL への通常の移動をするため、
該当の移動は約 5.3 秒かかっていた。通常の移動での誤作動は 0（Production の 200 回）。

## 変更

従来の 5 秒の安全策はそのまま残し、早めの判定を追加した（`early`・Resource Timing）:

- 移動先の RSC の応答が **この移動の開始の後に完了** していて、
- その完了から **1.5 秒** たっても URL が確定せず、
- 通信が **0.5 秒** 静か（最後の Resource Timing の完了から）なら、

5 秒を待たずに同じ URL へ通常の移動をする。RSC の応答がまだ（遅い回線）・prefetch 済みで RSC を取らない移動は、従来の 5 秒だけ。
戻る・進む・別のオリジン・同じ URL・新しい移動での取り消しは従来どおり。

## 閾値の根拠（RSC の応答の完了 → URL の確定）

| 計測 | 回数 | p50 | p90 | p99 / 最大 | 誤作動 |
|---|---|---|---|---|---|
| Production・PC・一覧 → 詳細（新しい RSC） | 60 | 23 ms | 38 ms | 278 ms | — |
| Production・携帯・一覧 → 詳細 | 60 | 23 ms | 47 ms | 62 ms | —（止まった移動 1 回・5 秒の安全策が動いた） |
| ローカル（新しい build）・PC | 40 | 14 ms | 32 ms | 60 ms | 0 |
| ローカル・携帯・通信を遅く（150 ms・200 kB/s） | 30 | 15 ms | 42 ms | 715 ms | 0 |

1.5 秒は Production の最大（278 ms）の 5 倍以上・遅い通信の最大（715 ms）の 2 倍以上。誤作動した場合の結果は同じ URL の通常の
読み込み（内容は同じ・約 1 秒の読み込みが増えるだけ）で、データは失われない。

## 期待する効果

止まった移動: 約 5.3 秒 → RSC の完了（約 0.3 秒）+ 1.5 秒 + 読み込み ≈ **約 2 秒**。通常の移動は変わらない。
本番の確認は `data/work/first-nav.mjs`（新しいブラウザーの最初の移動を繰り返す）で、戻しまでの時間と誤作動を記録する。
