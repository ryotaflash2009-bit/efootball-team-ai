# npm audit の評価と Next 16 の更新の計画（2026-10-11）

前回: `npm-audit-2026-10-07.md`（分類の詳細）。依存関係はその後変わっていない（main 594f29c 以降も package.json・lockfile の変更なし）。

## 1. 現状

- `npm audit --omit=dev`（本番の依存だけ）: **2 件**（high 1・moderate 1）
  - `postcss <=8.5.22`（next の同梱 `node_modules/next/node_modules/postcss` 8.4.31）: GHSA-qx2v-qp2m-jg93（stringify の出力で `</style>` を
    エスケープしない XSS）・GHSA-6g55-p6wh-862q / GHSA-fxqj-rqcc-2cmp / GHSA-r28c-9q8g-f849（CSS のコメントの `sourceMappingURL` で
    任意の `.map` ファイルを読む）。
  - `next 15.5.27`: 上の postcss を含むための moderate（next 自身の runtime の advisory ではない）。
- `npm audit`（開発の依存を含む）: 11 件（high 8・moderate 3）。内訳は前回と同じ（tailwindcss 3 系・eslint-config-next・上の 2 件）。

## 2. 到達の可能性（本番への影響）

| 観点 | 評価 |
|---|---|
| いつ動くか | next の同梱の postcss は **build の時**に自分の CSS（`globals.css`・Tailwind の出力）を処理する。サーバーの runtime・ブラウザーでは動かない |
| 利用者の入力の CSS | 処理しない（利用者が CSS を入力・アップロードする機能は無い） |
| `</style>` の XSS | 攻撃者が PostCSS の入力の CSS を制御できる場合だけ。入力は自分のソースだけ → 到達しない |
| `sourceMappingURL` のファイルの読み出し | 攻撃者が入力の CSS のコメントを制御できる場合だけ（build の機械のファイルを読む）。入力は自分のソースだけ → 到達しない。build は Vercel と CI（秘密は build に渡さない設計） |
| Production への影響 | なし（client の bundle・サーバーの runtime に postcss の code は無い） |
| 上流の修正 | next 15 系の最新（15.5.27・backport）も postcss 8.4.31 のまま。修正は next 16 系（16.4.0 は postcss 8.5.23 を同梱） |

結論: 警告を消すためだけの Next 16.4 への更新は**行わない**。下の計画で独立のフェーズとして行う。

## 3. Next 16.4 への更新の計画（将来の独立のフェーズ）

| 項目 | 確認すること |
|---|---|
| 版の要件 | next 16.4.0: Node `>=20.9.0`（CI と Vercel は Node 24・満たす）・React `^18.2.0 || ^19.0.0`（今 19.0.0・満たす） |
| 破壊的な変更（Next 16） | `middleware` の名前の変更（`proxy`）と挙動・Turbopack が既定・`next lint` の廃止（ESLint の直接の実行へ）・非同期の request API（`cookies()`・`headers()`・`params`）の同期の互換の削除・`next/image` の既定の変更（未使用）・キャッシュの API |
| 影響の大きい所 | 認証の callback（`exchangeCodeForSession`・`cookies()`）・`src/middleware.ts`（セッションの更新・noindex）・`sitemap.xml`（13,372 件の生成）・`robots`・セキュリティヘッダー（`next.config.mjs` の `headers()`）・`generateStaticParams` |
| Vercel | Next 16 の対応は Vercel の既定の build で可。Ignored Build Step なし（マージで本番が再デプロイ） |
| 計測 | build の時間・`.next/static` の大きさ（前後の比較）・hydration の black-box |
| テスト | `npm run verify`・build・全 13 の black-box・保存データありの hydration・検索の公開の確認（576 項目・sitemap・robots・canonical。共通のレイアウトと SEO に影響するため、この更新では必ず実行） |
| Tailwind 4 | 別のフェーズ（設定の移行: `@tailwindcss/postcss`・`@import "tailwindcss"`・テーマの変数）。Next 16 と同時にしない（原因の切り分けのため） |

GO（マージしてよい）: すべてのテスト・black-box が合格・build の時間と bundle の増加が 20% 以内・Preview で認証の callback（メールのリンク）・sitemap・
security headers・noindex の画面を確認・`npm audit --omit=dev` の postcss の high が消える。
NO-GO: callback・middleware・sitemap のどれかが変わる・hydration のエラー・検索の公開の確認の失敗。

Rollback: マージの revert の PR（`package.json`・lockfile・移行の変更を 1 つの PR にまとめる）→ 再デプロイ。データの変更は無い。

## 4. Dependabot PR #151（tailwindcss 3.4.17 → 4.3.3・postcss-selector-parser）

| 項目 | 評価 |
|---|---|
| 状態 | open（2026-10-06 作成）・CI 失敗 |
| 失敗の原因 | Tailwind 4 は `tailwindcss` を PostCSS の plugin として直接使えない（`@tailwindcss/postcss` が必要）。設定の移行の無い版の更新だけなので build が失敗 |
| セキュリティの修正 | build の道具（開発の依存）の advisory。本番には到達しない（`npm-audit-2026-10-07.md`） |
| 代替 | 無い（Tailwind 4 の移行は v1.1 の計画） |
| 判断 | **閉じる**。版の更新だけでは採用できず、移行は §3 の独立のフェーズで手で行う。閉じても、Dependabot は新しい版で再び作る（または手動の移行の PR で置き換わる） |
