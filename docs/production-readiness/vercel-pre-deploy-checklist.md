## 2. 現時点の総合判定: **Vercel接続前チェックリストは未達成(ただし進展あり)**

SQLite方式の判定(#1)・ライセンス(#5)は解決済み。#4・#7は「SQLite同梱を不採用にした」という決定により実質的に回避されたが、**アプリ本体の読み取り元がSupabaseへ完全に切り替わるまでは、Vercelデプロイに進む前提条件が整っていない**(現在のアプリはまだSQLiteを読み取っており、Vercel上ではその経路が動作しないため)。タスク要求(21章の停止条件)に照らし、**アプリ切替(次ブランチ)の完了まで、Vercel ImportまたはDeployへは進めない。**

## 3. 該当する停止条件(21章、タスク要求の一覧と照合)

| 停止条件 | 該当するか |
|---|---|
| SQLiteファイルがデプロイ成果物へ含まれない | 該当しない想定(SQLite同梱を不採用と決定したため、そもそも同梱しない設計) |

| node:sqliteがVercel Runtimeで保証されない | アプリ切替(次ブランチ)完了後は該当しなくなる見込み。**現時点ではアプリ本体がまだSQLiteを読み取っているため、切替完了まではこの制約が有効** |

## 4. Vercel料金・契約リスクの一覧(コードと想定利用量からの整理。正確な現行料金は断定しない)

`cost-estimate.md`(既存、2026-09-11)が3段階(身内テスト・招待制ベータ・一般ベータ)の月額概算を既に提示している。本章はそれを補足し、**本アプリのコード特性から見た固有のリスク**を追加する。

| 項目 | 本アプリでの状況 |
|---|---|
| Hobbyプランで技術検証可能か | 可能と見込む(個人・非商用の技術検証段階であれば要件を満たす)。ただし規約上の「非商用」要件への抵触有無は契約前にVercelの利用規約を確認すること。 |
| 商用利用時のプラン | Proプランへの移行が前提になる(`cost-estimate.md`Bの見積り参照)。 |
| Function呼び出し・CPU・メモリ | SQLite依存ルート(7経路)は他の軽量APIより1回あたりのメモリ使用量・実行時間が大きくなる可能性が高い(92 MiB規模のファイルを開くため)。無料枠の実行時間上限(Hobby: 100時間/月)への影響は、実際のアクセス量次第で変動し、今回は測定していない。 |
| 転送量(帯域) | 選手一覧・詳細等のJSONレスポンスは軽量だが、画像は自前プロキシ経由の中継のため、画像配信量がVercelの帯域(Hobby: 100 GB/月)に加算される。中継元(`efimg.com`等)側の帯域とは別に、**Vercel側の転送量としてもカウントされる**点に注意。 |
| 画像最適化 | Next.js標準の`next/image`最適化機能は`next.config.mjs`で未設定(`images.remotePatterns`なし)であり、**現状は使っていない**。画像最適化のFunction呼び出し課金は発生しない見込み。 |
| ビルド時間・デプロイ回数 | Production Buildはローカル実測で数十秒〜1分程度(実測値は環境依存のため断定しない)。Hobbyのビルド時間枠(6,000分/月)を通常の開発ペースで超過する可能性は低いと見込むが、未検証。 |
| Function bundle | `sqlite-production-compatibility-audit.md`3章のとおり、SQLite依存の7経路が個別にDBを内包する場合、合計デプロイサイズが数百MB規模になる可能性がある(重複排除の有無は未検証)。 |
| ログ保持・監視 | 現状Sentry等の監視サービスは未導入(`decision-record.md`で将来導入を推奨、今回は導入していない)。 |
| 帯域超過・予期しない従量課金 | Proプラン移行後は帯域超過分が$0.15/GB($単位、`hosting-options.md`引用)で課金される。画像中継量が想定より多い場合、この従量課金が発生し得る。 |
| Spend Management・費用上限 | Vercelにはプロジェクト単位の使用量アラート機能がある(`owner-actions.md`7章)。契約時に閾値設定を行うことを推奨するが、**今回は設定していない**。 |
| チームメンバー追加・独自ドメイン・ドメイン費用 | 個人開発の現段階では該当なし。独自ドメイン取得時の概算費用は`cost-estimate.md`参照。 |
| SMTP費用 | `smtp-plan.md`参照(未選定・未契約)。 |
| Supabase費用 | `cost-estimate.md`参照。現状Freeプランの範囲内(ユーザーA・Bのみ)。 |

**Claude Codeは契約・支払い・カード登録・プラン変更を一切行わない。** ユーザーがVercel画面でプラン選択・支払いを求められた場合は、費用と自動更新条件を確認するまで進めないこと。

## 5. 結論(2026-09-14更新)

**現時点ではVercelアカウント登録・GitHub連携・Import・Deployのいずれも案内しない。** ライセンス確認(2026-09-14解決済み)に加え、SQLite方式そのものの判定も解決済み(不採用、Supabase `reference_data`への移行を採用・実データ投入済み)。残る前提条件は**アプリ本体のデータ読み取り元をSQLiteからSupabaseへ実際に切り替えること**(`app-hybrid-switch-implementation-plan.md`、次ブランチ`feat/supabase-reference-data-switch`で実施予定、今回のタスクでは未着手)。この切替が完了し、アプリがSQLiteに依存しなくなるまで、Vercelへの接続・検証は行わない。
