# カスタムSMTP導入計画(2026-09-14)

調査日: 2026-09-14。本書は計画のみであり、**今回SMTP設定は一切変更していない**。

---

## 1. 現状(標準SMTP)の課題

- Supabase Auth既定の標準SMTPは、Supabase名義で送信される(差出人ブランドが「eFootball Team AI」にならない)。
- 本番用途を想定した設計ではなく、**送信制限が厳しい**(Supabase公式が明言する既知の制約)。
- 複数利用者への登録メール配信には適さない。

## 2. 今回の監査での方針

- Vercel互換性監査(本フェーズ)では、SMTP設定・Supabaseダッシュボードの変更は**行っていない**。
- ただし、「身内テストで新規登録を依頼する前に、カスタムSMTPが必要かどうか」をリリースゲートとして判定することが求められているため、以下のとおり判定する。

## 3. 判定: 標準SMTPのまま第三者(身内であっても)テストを一般公開しない

理由:
- 標準SMTPは送信数上限が低く、複数人が同時に新規登録・パスワード再設定を行うと制限に抵触する可能性が高い。
- 差出人が「Supabase」名義になることは、身内テストであっても受信者に不審なメールと誤解される可能性がある。
- **結論: 標準SMTPのまま一般公開可能とは判定しない。** 少なくとも身内テスト(5人程度)より前の、開発者本人だけの技術検証段階では標準SMTPのままでよいが、**第三者(身内を含む)へ新規登録を依頼する段階に進む前に、カスタムSMTPの導入を完了させることをリリースゲートとする**。

## 4. 導入が必要になる要素(計画のみ)

| 要素 | 内容 |
|---|---|
| 独自ドメイン | 本番URLと合わせて取得(`cost-estimate.md`の年額$10〜$20程度の見積りを参照) |
| メール用サブドメイン | 例: `mail.<ドメイン>`。本体ドメインの評判(レピュテーション)への影響を分離するため推奨 |
| カスタムSMTP事業者 | 未選定(候補: Resend, SendGrid, Postmark等。具体的な料金比較は今回実施していない) |
| 差出人名 | 「eFootball Team AI」 |
| 送信元アドレス | `no-reply@<メール用サブドメイン>`等 |
| SPF / DKIM / DMARC | カスタムSMTP事業者の指示に従いDNSレコードを設定(なりすまし対策・到達率向上のため必須級) |
| 対応メール種別 | 確認メール(サインアップ)・再送メール・パスワード再設定メール |
| 多言語対応 | 日本語・英語(既存の`i18n`辞書構造を踏襲する想定) |
| レート制御 | 既存の60秒クールダウン(`src/lib/supabase/resend-cooldown.ts`で確認済み)・429案内文言は既存実装を流用可能と見込む |
| 送信上限 | カスタムSMTP事業者のプランに依存(未調査) |
| 不達監視・バウンス・スパム判定 | カスタムSMTP事業者側のダッシュボード機能に依存(未調査) |
| 費用 | 未調査(事業者・送信数次第。`cost-estimate.md`の「招待制ベータ」区分で「$0〜数ドル」と概算のみ記載されている) |

## 5. 未確定事項
