```json
{"i":"8554053","e":"Ismail Nasrallah","j":"イスマイル ナスララー","c":"伊斯梅尔·纳斯鲁拉","o":120}
{"i":"8554076","e":"Safi Belal","j":"サフィ ベラル","c":"萨菲·比拉勒","o":120}
{"i":"89138556575063","e":"Lionel Messi","j":"リオネル メッシ","c":"利昂内尔·梅西","o":107}
```

- 1件目のキー: **`[i, e, j, c, o]`**
- research.txt の推測になかった **`c` キー**が存在した（値は中国語表記の選手名）。

## 短縮キーの判定（実測）

| キー | 型 | 例 | 判定 | 根拠 |
|---|---|---|---|---|
| `i` | 数値（桁数がまちまち。7〜15桁） | `"8554053"`, `"89138556575063"` | **選手ID** | 一意の識別子。桁が大きいものがあるため、精度劣化を避けて**文字列として保存**した |
| `e` | 文字列 | `"Lionel Messi"` | **英語名** | ラテン文字。100件すべて英字を含む |
| `j` | 文字列 | `"リオネル メッシ"` | **日本語名** | カタカナ表記 |
| `c` | 文字列 | `"利昂内尔·梅西"` | **中国語名（簡体字）** | research.txt になかった追加フィールド。今回の動作版では未使用（保存もしない） |
| `o` | 数値 | `120`, `107`, `97` | **OVR（総合値）** | 0〜120 の範囲。ただし research.txt の例（97）より高い値（107, 120）が多数 |

### `o`（OVR）に関する注意（未確認事項）

- 先頭付近に `o=120` の選手が多い（例: Ismail Nasrallah, Safi Belal）。研究資料の例は `o=97`（Melvin Bard）だった。
- 可能性:
  - `o` は「最大レベル時の OVR」で、`120` は上限付近のカード。
  - もしくは特定カード種別（Epic/Legend 等）の値。
  - player-index.json の並び順は OVR 降順ではない（ID 昇順でもない）。並び基準は未確認。
- **確定には、個別選手ページ（eFHUB 画面）との突き合わせが必要**（第4章の調査 B）。
  今回の動作版では `o` を「OVR」として表示するにとどめる。

### 並び順（未確認）

- 先頭は ID の小さい特殊カード（`8554053` 等）、3件目以降に大きい ID（`89138556575063` 等）。
- ID 昇順でも OVR 順でもない。追加調査が必要。

## 実装への反映（実施済み）

- 選手 ID は **文字列**として保存（`scripts/fetch-player-index.mjs` が JSON パース前に `"i":<数値>` → `"i":"<数値>"` へ変換）。
- Zod スキーマ（`src/lib/schema.ts`）は `.passthrough()` で追加キー（`c` など）を許容。内部型は `{ id, nameJa, nameEn, ovr }` に正規化。
- 保存形式:
  - `src/data/players.sample.json` = `{ "players": [ { id, nameJa, nameEn, ovr }, ... ] }`（100件）
  - `src/data/meta.json` = 取得元・取得日時・件数・チェック結果

## 取得失敗時の設計（確認済み・今回は成功したため未発火）

- ネットワークエラー / 非200 / 非JSON / 非配列 / 有効0件 → **ファイルを書かず終了コード1**。再取得しない。
